# 풍력 입지타당성 검토 자동화 시스템

**AI 해커톤 기획서**

| | |
|---|---|

| 분야 | 재생에너지 사업개발 · 공공데이터 · 업무 자동화 |

## 요약

신규 육상풍력 후보지가 나오면 입지 검토에만 **며칠**이 걸립니다. 확인해야 할 규제가 60개를 넘고, 소관 기관과 조회처가 제각각이며, 발전기 위치를 한 번 옮길 때마다 그 일을 처음부터 다시 해야 하기 때문입니다.

이 시스템은 **지도에 발전기 위치를 찍는 것만으로** 공공 API 10여 곳을 한 번에 조회해 규제 62개 항목을 판정하고, 근거와 확인처를 붙인 검토 보고서(docx)를 만듭니다. 첫 검토는 수 분, **같은 지역의 재검토는 수십 초**입니다.

핵심은 속도가 아니라 **재검토 비용을 0에 가깝게 만든 것**입니다. 배치안을 바꿔 보는 일이 공짜가 되면, 종전에는 시간이 없어 한두 안만 보던 것을 열 개를 보게 됩니다. 검토의 속도가 아니라 **검토의 밀도**가 달라집니다.

## 1. 문제 정의

### 1.1 지금은 이렇게 합니다

사업개발 담당자가 후보지 하나를 검토할 때 밟는 절차입니다.

| 확인 대상 | 조회처 | 성격 |
|---|---|---|
| 용도지역·지구, 필지 지역지구 | 토지이음, 토지이용계획확인원 | 필지마다 개별 열람 |
| 토지 소유구분, 지목, 면적 | 정부24 토지(임야)대장 | 필지마다 개별 열람 |
| 산지구분(보전·준보전) | 토지이용계획확인원 | 인허가 난이도를 가르는 최대 변수 |
| 생태자연도, 자연공원, 백두대간 | 환경공간정보서비스 | 지도 서비스별로 따로 |
| 문화유적분포지도, 조사구역 | 국가유산청 | 별도 시스템 |
| 군사시설보호구역, 비행안전구역 | 관할부대 협의 | 좌표 기반 공개 API 없음 |
| **지자체 이격거리 조례** | 자치법규정보시스템 | **지자체마다 조문·거리·대상이 다름** |
| 정온시설·주거밀집 | 건축물대장 + 현장 | 호(戶) 수 산정 규칙이 조례에 따로 있음 |
| 전력계통 연계 | 한전 | 변전소 위치는 비공개 |
| 풍황 | 기상청 · 재분석 자료 | 관측 높이가 허브고도와 다름 |

### 1.2 무엇이 시간을 잡아먹는가

**① 항목이 많고 조회처가 흩어져 있습니다.** 62개 항목의 소관이 국토부·환경부·산림청·국가유산청·국방부·지자체·한전으로 나뉘어 있습니다. 사이트를 오가는 시간이 판단하는 시간보다 깁니다.

**② 호기 수만큼 반복합니다.** 10기 배치면 필지 조회와 이격 판정을 10번 합니다.

**③ 조례가 지자체마다 다릅니다.** 이격거리가 도시·군계획 조례에 있는 곳, 별표에만 있는 곳, 아예 별도 조례로 제정한 곳이 섞여 있습니다. 조문을 찾는 것 자체가 일입니다.

**④ 그리고 배치는 반드시 바뀝니다.** 이격거리에 걸린 호기를 옮기면 위 과정을 **처음부터 다시** 합니다. 이것이 가장 큰 낭비입니다. 시간이 없으니 배치안을 한두 개만 보게 되고, 더 나은 배치를 찾지 못한 채 다음 단계로 넘어갑니다.

> **문제의 본질은 "한 번 검토가 느리다"가 아니라 "다시 검토할 수 없다"입니다.**

## 2. 해결 방안

### 2.1 접근

좌표를 입력으로 삼아 **모든 조회를 한 번에, 기계가** 수행합니다.

```
지도 클릭 (1호기 → N호기)
        ↓
발전기 원 + 연결선 회랑으로 검토 범위 생성
        ↓
공공 API 10여 곳 병렬 조회 · 결과 캐시
        ↓
규제 62개 항목 판정 (4단계) · 면적 분포 산출
        ↓
검토 보고서(docx) · 배치안 저장
```

### 2.2 두 가지 검토 모드

| 모드 | 입력 | 쓰임 |
|---|---|---|
| **지점·배치선 검토** | 1호기부터 순서대로 클릭 | 발전기 위치가 정해진 단계. 한 곳만 찍으면 단일 지점 검토 |
| **구역 검토** | 폴리곤 꼭짓점 | 사업 구역만 정해진 초기 단계. 어디가 얼마나 쓸 수 있는지 |

배치선 모드는 발전기 원(기본 500m)과 그 사이를 잇는 연결선 회랑(기본 100m)을 합쳐 검토 범위로 씁니다. **이격거리 조례는 발전기 위치에만 적용합니다** — 조례가 규율하는 것은 발전시설이지 집전선로가 아니기 때문입니다.

### 2.3 산출물

**검토 보고서(docx)** — 종합판정 · 입지조건 종합평가(62개 항목) · 호기별 비교표 · 리스크 요약 · 면적 분포와 가용면적 · 제약도(위성영상 위 중첩) · 풍황 · 전력계통 · 조례 경과규정.

**배치안 저장** — 사업 아래 `배치안 1, 2…`로 좌표와 검토 조건을 남깁니다. 불러오면 지도와 조건이 그대로 복원되고, 여러 안을 나란히 견줄 수 있습니다.

## 3. 설계 원칙 — 이 시스템의 차별점

자동화의 진짜 위험은 느린 것이 아니라 **조용히 틀리는 것**입니다. 인허가 판단에 쓰이는 자료가 잘못되면 자동화로 아낀 시간보다 훨씬 큰 비용이 발생합니다. 그래서 다음을 설계의 축으로 삼았습니다.

### 원칙 1 — 판정을 대신하지 않는다

이 시스템은 가부를 선고하지 않습니다. **근거 규정과 확인처를 붙여 담당자가 확인할 것을 좁혀 주는 데까지**가 역할입니다. 조건부·확인 필요 항목에는 근거 법령·조문과 실제로 밟아야 할 절차, 조회 기관·사이트를 함께 싣습니다.

### 원칙 2 — 모르는 것은 모른다고 말한다

판정은 4단계입니다.

| 기호 | 판정 | 뜻 |
|---|---|---|
| ● | 불가 | 조문이 직접 금지 |
| ▲ | 조건부 | 협의·저감으로 진행 가능 |
| ◇ | **확인 필요** | **자동으로 단정하지 않았다** |
| ○ | 해당없음 | 검토 범위에 해당 사항 없음 |

`확인 필요`는 실패가 아니라 설계된 상태입니다. 그리고 그 안에서도 **재시도로 풀리는 것과 아닌 것**을 구분합니다 — 인증키 미설정 / 조회 실패 / 자료 없음 / 판정 기준 없음 / 자동 판정 대상 아님.

“조례를 확인했는데 이격 규정이 없다”와 “조례를 못 찾았다”는 전혀 다른 사실입니다. 앞은 그 지자체에 제한이 없다는 **확정 정보**이고, 뒤는 모른다는 뜻입니다. 이를 뭉뚱그리면 멀쩡히 쓸 수 있는 땅을 버리거나, 걸리는 땅을 가용으로 셉니다.

### 원칙 3 — 가용면적을 하나로 말하지 않는다

생태자연도 1등급도 백두대간 핵심구역도 법률상 예외 행위가 있어 「불가」가 아닙니다. 여기서 임의로 '배제구역'을 정하면 **코드가 법령에 없는 금지를 만들어내는** 셈이 됩니다. 그래서 두 가지로 병기합니다.

```
엄격 가용    = 아무 규제 레이어에도 걸리지 않는 면적
협의 포함    = 엄격 가용 + 조건부 면적
```

어느 쪽을 쓸지는 사업 판단이지 계산의 몫이 아닙니다.

### 원칙 4 — 추측해서 잇지 않는다

행정구역 개편으로 지적 자료와 국가공간정보의 법정동코드가 어긋난 지역이 있습니다. 코드 앞자리를 훑으면 응답이 오는 조합이 여럿 나오는데, **응답이 왔다는 것은 맞는 필지라는 증거가 아닙니다.** (실제로 완도군 필지를 조회하면서 고흥군에서도 응답이 왔습니다 — 그 군에도 같은 읍면동 코드에 같은 지번이 있었습니다.)

그래서 **응답에 실린 소재지 주소로 대조해 시군구명과 읍면동명이 함께 맞을 때만** 연결합니다. 확인되지 않으면 연결하지 않고, 왜 안 되는지를 항목 사유에 적습니다. 남의 땅 자료를 이 사업지 것으로 싣는 것보다 낫습니다.

### 원칙 5 — 한계를 본문에 적는다

보고서는 메일로 나가고 인쇄되고 보관됩니다. 표에서 숫자만 발췌돼 다른 문서에 인용되는 순간 단서는 떨어져 나갑니다. **각주보다 숫자가 오래 삽니다.** 그래서 다음을 부록이 아니라 본문에 넣습니다.

- 조례 이격 면적이 대장상 주택 기준의 **상한선**이라는 사실
- 용도 미확인 건물 수, 조회 실패 레이어, 판정 보류 면적
- 면적 산출에 반영하지 못한 조항(건물이 아닌 이격 대상 등)
- 점수 산식과 그 검토의 실제 계산 과정

## 4. 시스템 구성

### 4.1 아키텍처

```
[React 18 + Vite + Leaflet]  지도·검토 조건·결과 화면
              │  REST
[Django 5 + DRF]
   ├─ 검토 엔진        62개 항목 어댑터 · 판정 규칙 DB
   ├─ 공간 연산        shapely · pyproj (EPSG:5179 미터 좌표계)
   ├─ 조례 파이프라인   자치법규 원문 수집 → 조문·별표 파싱 → 이격거리 추출

   └─ 작업 제어        진행률 · 협조적 취소
              │
[PostgreSQL] 판정 규칙 · 조례 원문 · 배치안    [Redis] 응답 캐시 · 작업 상태
              │

                한전 · 기상청 · KIER · 건축물대장 · OpenStreetMap
```

## 5. 기술적으로 풀어낸 문제

해커톤 심사에서 볼 만한, 실제로 막혔다가 뚫은 지점들입니다.

### 5.1 조례를 사람이 읽지 않고 기계가 읽게 하기

지자체 이격거리 조례는 형식이 제각각입니다. 조문에 있는 곳, **별표에만** 있는 곳, 도시·군계획 조례가 아닌 **별도 조례**로 제정한 곳이 섞여 있습니다.

- 자치법규 API로 원문을 받아 조문 → 별표 순으로 훑고, 첫 조례에 규정이 없으면 다음 후보로 넘어갑니다
- 별표는 표 형식이라 **풍력 열만** 골라냅니다
- `2,000미터` / `2000m` / `1.5킬로미터` 표기와 `(단, 5호 미만은 500미터)` 같은 단서 괄호를 함께 해석합니다
- 이격거리가 **아닌** 수치(울타리 높이 2m 등)를 걸러내는 문맥 규칙을 둡니다

### 5.2 "5호 이상 주거밀집지역"을 실제로 판정하기

조례의 정의 조항을 그대로 옮겼습니다.

> 주택 간 **직선거리 50미터 이내**에 인접한 주택의 합이 **5호 이상**이면 주거밀집지역. 단, **부속 건축물은 제외**한다.

- 건축물대장 주용도로 주택·축사·정온시설·부속건축물을 갈라냅니다
- 주택만 모아 50m 연쇄 군집(union-find)으로 호수를 셉니다
- 5호 이상 군집과 미만 군집에 **다른 거리**를 적용합니다

이 분류를 붙이기 전에는 창고 한 채까지 주거 이격 2,000m를 만들어 내 검토 구역의 **97.8%가 배제**로 잡혔습니다. 분류 이후 **83.0%**로 내려갔고, 무엇보다 그 숫자가 조문에 근거하게 됐습니다.

### 5.3 실용적인 속도

| 문제 | 해결 | 결과 |
|---|---|---|
| 건물마다 버퍼를 씌우면 수천 개 도형 합집합 | 100m 격자로 뭉치고 격자 대각선 절반(71m)을 안전 여유로 가산 | 300초+ → **10초** |
| V-World 폴리곤 요청 면적 10km² 상한 | 3km 격자 타일 분할 + 격자 스냅으로 캐시 재사용 | 넓은 구역 조회 가능 |
| Overpass 사용량 제한으로 보고서 20분 초과 | 미러 3곳 + 좌표 격자 스냅 + 미러 전환 시 백오프 생략 | 근본 원인 제거 |
| 조회가 길어 화면이 묶임 | Redis 기반 진행률 폴링 + **협조적 취소**(서버 작업까지 실제 중단) | 배치를 바꾸는 중 언제든 중단 |

### 5.4 조례 개정 이전 사업의 소급 미적용

조례 개정 전에 발전사업허가를 받은 사업은 부칙 경과조치로 종전 기준이 적용될 수 있습니다. **이 사실을 모르면 멀쩡한 사업이 불가로 판정됩니다.**

- 조례의 시행일과 **부칙 경과조치를 담은 개정의 시행일**을 구분해 저장합니다
- 발전사업허가일을 입력하면 대조해 경과규정 검토 대상으로 표시하고 부칙 원문을 함께 싣습니다
- **면제를 판정하지는 않습니다** — 문언이 조례마다 다르고("허가를 받은 경우" / "실시계획 승인" / "착공"), 최종 판단은 관할 지자체의 몫입니다

## 6. 실증

### 6.1 완도 흑백풍력 (백일도·동화도)

실제 검토 대상지로 시스템을 돌려 **잠재적 오판을 잡아냈습니다.**

행정구역 개편으로 지적·지오코딩은 새 법정동코드를, 건축물대장과 국가공간정보는 종전 코드를 쓰고 있었습니다.

```
지적 · 지오코딩   12850 31028
대장 · NED        46890 31028      ← 앞 5자리만 다름
```

지적에서 받은 코드를 그대로 넘기니 조회가 전부 0건이었고, 건물 용도를 한 동도 확인하지 못해 **조례 이격 버퍼가 아예 만들어지지 않았습니다.**

| 항목 | 대응 전 | 대응 후 |
|---|---|---|
| 건축물대장 조회 | 0건 | **206건** (단독주택 140) |
| 건물 용도 분류 | 미확인 122동 | 주택 21 · 대상아님 19 · 미확인 82 |
| 토지 소유구분 · 필지 지역지구 | 확인 필요 | 사유지 확인 · 지역지구 9종 |
| 산지구분 · 토지특성 | 확인 필요 | 공익용·임업용·준보전 / **맹지** |
| 제약 없음 면적 | 119.3 ha | **58.2 ha** |
| 조례 이격 면적 | 0 ha | **64.1 ha** |

**가용면적이 두 배 가까이 부풀어 있었습니다.** 이 상태의 숫자로 사업성을 판단했다면 뒤늦게 뒤집혔을 값입니다.

### 6.2 삼척 천봉풍력

삼척시 이격거리 조례(2,000m) 개정 **이전에** 발전사업허가를 취득한 사업입니다. 경과규정 기능으로 조례 시행일과 허가일을 대조해 검토 대상으로 표시하고 부칙 원문을 보고서에 실었습니다.

### 6.3 측정된 처리 시간

| 작업 | 소요 |
|---|---|
| 1지점 검토 (62개 항목 포함) | **2.1초** |
| 2지점 검토 (반경 500m) | 5.1초 |
| 10지점 검토 실행 | 약 1분 (첫 조회) / 20초 내외 (재실행) |
| 보고서 생성 — 첫 생성 | 5~10분 |
| 보고서 생성 — 같은 배치 재생성 | **6~10초** |

## 7. 기대 효과

### 7.1 소요시간

> ⚠️ 아래 '종전' 값은 **팀 내 경험에 기반한 추정**이며 측정치가 아닙니다. 제출 전 실제 소요시간으로 대체하시기 바랍니다. '현재' 값은 실측입니다.

**10기 배치 1건, 최초 검토 기준**

| 단계 | 종전 (추정) | 현재 (실측) |
|---|---|---|
| 필지·지역지구·소유구분 조회 | 2~3시간 | 자동 |
| 조례 검색·조문 판독 | 1~2시간 | 자동 |
| 환경·문화재·군사·항공 조회 | 3~5시간 | 자동 |
| 계통·풍황 자료 수집 | 2~4시간 | 자동 |
| 취합·보고서 작성 | 4~8시간 | 자동 |
| **합계** | **12~22시간 (2~3일)** | **5~10분** |

### 7.2 진짜 효과는 재검토에 있습니다

| | 종전 | 현재 |
|---|---|---|
| 배치 1안 검토 | 2~3일 | 5~10분 |
| **배치 2안 재검토** | **다시 2~3일** | **20초 ~ 수 분** |
| 현실적으로 검토 가능한 배치안 수 | 1~2개 | 제한 없음 |

배치를 바꿔 보는 비용이 사실상 사라집니다. 이격거리에 걸린 호기를 옮기고 다시 돌리는 일을 **열 번 해도 부담이 없습니다.** 검토가 빨라지는 것을 넘어, **더 나은 배치를 실제로 찾게 됩니다.**

### 7.3 그 밖에

- **판단 근거가 문서로 남습니다** — 근거 법령·조문·조회처가 보고서에 붙어 감사 추적이 됩니다
- **담당자 편차가 줄어듭니다** — 누가 검토해도 같은 62개 항목을 같은 기준으로 봅니다
- **놓침이 줄어듭니다** — 사람이 매번 62개를 빠짐없이 확인하기는 어렵습니다

## 8. 한계와 다음 단계

숨기지 않고 보고서 본문에도 그대로 적는 내용입니다.

| 한계 | 현재 처리 | 다음 단계 |
|---|---|---|
| 건물이 아닌 이격 대상(도로 등) | 면적 산출에서 제외하고 **그 사실을 명시** | 도로 등급별 레이어 연동 |
| 건축물대장 미등재 건물 13~18% | 버퍼 없이 '용도 미확인 N동'으로 별도 집계 | 항공영상 기반 보조 판별 검토 |
| 주민등록 실거주·빈집 여부 | 공개 자료 없음 — **상한선임을 명시** | 지자체 협조 시 반영 |
| 변전소 좌표 비공개 | OpenStreetMap 의존, 한전 공급관계 병기 | 사내 확보 좌표 주입 지원 |
| 풍황은 관측소 기반 추정 | 허브고도 100m 환산 + **실측 권고 상시 표기** | 사내 계측 데이터 연동 |
| 군사·항공 일부 항목 | 좌표 기반 공개 API 없음 | 관할부대 협의 절차 안내로 대체 |
| 외부 API 장애 | 실패 레이어를 '보지 못한 제약'으로 경고 | 자체 OSM 데이터 적재 검토 |

**개발 로드맵**

1. 도로 이격 레이어 연동 — 완도 사례처럼 결정적 제약이 될 수 있음
2. 조례 커버리지 확대 — 현재 6개 지자체 → 풍력 추진 지역 전체
3. 행정구역 개편 대응표 확대 — 확인 기반 자동 탐색 명령 이미 구현
4. 사내 실측 풍황·변전소 좌표 주입
5. 인허가 로드맵과 일정 시뮬레이션 연계
