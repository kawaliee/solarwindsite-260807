## 0. 먼저 확인이 필요한 한 가지 — 태양광의 입력 단위

기획서와 지시가 다르게 읽힙니다.

| 출처 | 태양광 모드의 정의 |
|---|---|
| 기획서 §3.3 / §7.5 R-06~R-09 | **필지 발굴** — 화면 범위 필지를 4등급으로 채색(스크리닝) → 필지 클릭 시 PNU 폴리곤 정밀판정 → 후보 필지 담기·비교 |
| 지시 | **구역 검토** — 지도에 사업구역 폴리곤을 그려 검토 |

이번 1차 구현은 **구역 검토**로 넣었습니다. 이유는 셋입니다.

1. 지시가 두 번(범위 선택, 재확인) 모두 구역 검토였습니다.
2. 구역(면) 검토는 이미 엔진에 있어 **오늘 바로 동작**합니다. 필지 스크리닝은 새 계층(타일·사전연산·필지 등급화)이라 별도 개발입니다.
3. 필지 정밀판정은 구역 검토의 특수한 경우입니다 — 폴리곤이 필지 경계인 것뿐이라, 지금 만든 것이 그대로 재료가 됩니다.

**필지 발굴 모드까지 가려면 §5의 2·3단계가 추가로 필요합니다.** 해커톤 제출이 기획서 기준이라면 그 일정을 잡아야 합니다.

## 1. 설계 원칙 — 무엇을 공유하고 무엇을 가르는가

풍력 검토 코드는 약 13,500줄입니다. 그중 에너지원과 무관한 것이 대부분입니다.

```
                    [공용 엔진 — 그대로 공유]
   규제 레이어 62종 · 필지/지적 · 산지구분 · 소유구분 · 생태자연도
   국가유산 · 군사보호구역 · 행정경계 분할 · 면적 4분할 · 제약도
   협조적 취소 · 격자 캐시 · docx 보고서 골격 · 계통(KEPCO/OSM)
                              ▲
        ┌─────────────────────┴─────────────────────┐
        │  갈리는 것은 넷뿐 (energy.py 한 곳에 모음)   │
        │   ① 이격거리 조례   ② 인허가 절차            │
        │   ③ 적용 법령      ④ 자원 항목(풍황)         │
        └───────────────────────────────────────────┘
```

**따라서 규제 레이어를 하나 고치면 풍력·태양광에 동시에 반영됩니다.** 코드를 복제했다면 앞으로 모든 수정을 두 번 해야 했을 것입니다.

에너지원별로 갈리는 값은 백엔드 `backend/apps/windsite/energy.py`, 화면 `frontend/src/features/windsite/energy.ts` 두 파일에 표로 모았습니다. 다음 에너지원(예: ESS 부지)을 붙일 때 고칠 곳도 이 두 곳입니다 — 기획서 N-04(확장성)가 요구한 구조입니다.

## 2. 이번에 완료한 작업

### 2.1 UI — 카테고리 완전 분리 ✅

- 사이드바에 **`태양광 입지검토`** 메뉴 신설 (풍력 바로 아래, 태양 아이콘)
- 상단바 제목 `태양광 입지타당성 검토` · 부제 `사업구역 제약도 · 태양광 이격거리 조례 · 가용면적 산출`
- **두 화면의 상태는 서로 섞이지 않습니다.** `ViewBoundary`의 key가 화면 이름이라, 메뉴를 옮기면 화면이 새로 만들어집니다. 풍력에서 찍은 좌표·검토반경·허가일이 태양광으로 새지 않습니다.
- 태양광 화면은 **구역 검토 모드만** 노출합니다(호기 배치선은 태양광에 성립하지 않음). 배치안 저장·후보지 비교 탭도 호기 좌표 기능이라 숨겼습니다.

### 2.2 조례 파이프라인 — 에너지원별 판독 ✅

가장 중요한 부분입니다. 풍력과 태양광은 **같은 조례의 같은 별표에 나란히** 실립니다.

```
구 분          태양에너지 설비      풍력에너지 설비
도로            500미터 이상 이격    1,000미터 이상 이격
주거밀집지역     500미터 이상 이격    2,000미터 이상 이격
```

기존 파서는 풍력 열만 읽도록 고정돼 있었습니다. 이제 에너지원에 따라 **읽을 열을 고릅니다.** 실측 검증 결과:

| 에너지원 | 도로 | 주거밀집 |
|---|---|---|
| 풍력 | 1,000 m | 2,000 m |
| 태양광 | 500 m | 500 m |

- 표가 없는 조례는 항목 기호(`마. 태양광발전시설은 …`)로 해당 구간만 잘라냅니다.
- 머리글에 '태양'과 '풍력'이 **둘 다** 없으면 표로 보지 않습니다 — 열을 추측하지 않습니다.
- 자동 수집 실패 기록(캐시)도 에너지원별로 나눴습니다. 풍력 규정이 없다고 태양광 조회까지 막히던 문제를 없앴습니다.
- 수집 커맨드에 `--energy` 추가:

```bash
docker compose exec backend python manage.py sync_ordinances --sigungu 해남군 --sido 전라남도 --energy SOLAR --apply
```

`--energy ALL` 을 주면 풍력·태양광을 차례로 수집합니다.

### 2.3 판정 엔진 ✅

- `evaluate()` / `compute()` / `evaluate_points()` / 보고서 생성에 `energy`를 관통시켰습니다.
- **풍황 어댑터는 태양광에서 제외**됩니다. 판정에 쓰이지도 않는 풍속이 태양광 보고서에 근거처럼 남는 것을 막습니다.
- 정온시설 동심원 분석의 반지름이 **태양광 조례 거리**로 그려집니다(넘기지 않으면 풍력 2,000m로 그려져 가용면적이 통째로 틀어졌을 자리입니다).
- 인허가 로드맵 분기: 풍력은 부지 종류를 못 읽으면 산지로 가정하지만(능선 입지), 태양광은 농지·임야·잡종지가 섞여 있어 **가정하지 않습니다.**

### 2.4 인허가·법령 — 정직한 빈 목록 ✅

`PermitStep` · `LawReference` · `SiteEvaluation`에 `energy_type` 컬럼을 추가했습니다(마이그레이션 `0008_energy_type`, 기존 레코드는 전부 `WIND`).

태양광 절차·법령은 아직 미등록이라 **빈 목록**이 나갑니다. 화면은 그 이유를 밝힙니다:

> 태양광 인허가 절차는 아직 등록되지 않았습니다. 절차가 없다는 뜻이 아니라 데이터가 없다는 뜻이며, 풍력 절차를 대신 보여 주지 않습니다(발전사업허가 소관·용량 경계가 다릅니다).

풍력 절차를 그대로 보여 줬다면 발전사업허가 소관(풍력 3MW 초과 산업부 / 태양광 3MW 이하 시·도)부터 틀린 문서가 사업 판단에 쓰였을 것입니다.

### 2.5 보고서 ✅

- 표제 `태양광 입지타당성 검토 보고서`, 파일명 `태양광구역검토_YYYY-MM-DD.docx`
- 풍황 절(KIER 격자·허브고도 환산)은 태양광에서 빠지고, 전력계통·정온시설은 그대로 실립니다.

## 3. 사용자가 직접 해야 할 일 (내가 대신할 수 없는 것)

### 3.1 🔴 [최우선] 국가법령정보 OPEN API 서버 IP 등록

**지금 태양광 조례가 한 건도 수집되지 않는 유일한 원인입니다.** 코드는 정상이고, API가 요청을 거절하고 있습니다.

실제 응답:
> 사용자 정보 검증에 실패하였습니다. OPEN API 호출 시 사용자 검증을 위하여 정확한 서버장비의 IP주소 및 도메인주소를 등록해 주세요.

law.go.kr은 인증키(OC)와 **별개로** 계정에 등록된 서버 공인 IP를 대조합니다.

1. [open.law.go.kr](https://open.law.go.kr) → OPEN API → OPEN API 신청
2. 현재 서버의 **나가는 공인 IP** 등록 (확인: `curl ifconfig.me`)
3. 유동 IP면 바뀔 때마다 갱신해야 하므로 **고정 IP 또는 고정 출구**를 두는 편이 낫습니다
4. 운영 전환 시 `LAW_API_OC`를 자체 인증값으로 교체 (현재 공용 데모 계정 `OC=test` 사용 중)

> 기획서 §7.6에도 "국가법령정보 API는 서버 공인 IP 등록제 — 운영 서버 IP 고정 및 변경 절차 문서화"로 이미 적혀 있는 항목입니다.

### 3.2 🟠 시범 지자체 3곳 선정 + 조례 원문 검수

기획서 §7.1 MVP 범위가 "시범 지자체 3곳 원문 대조 등록"입니다. 제가 할 수 없는 것은 **어느 지자체를 고를지**와 **추출 결과가 원문과 맞는지 사람 눈으로 대조**하는 일입니다.

- 태양광 사업 검토 예정지 기준으로 3곳 지정해 주십시오
- IP 등록 후 제가 수집을 돌리고, 추출된 거리·대상·조문을 원문과 나란히 놓은 검수표를 만들어 드리겠습니다
- 화순군 사례처럼 **2차 자료(언론보도) 기반 값이 원문과 다른 경우가 실제로 있었습니다**(1,200m로 알려졌으나 원문은 2,000m). 검수 없이 넘기면 안 됩니다

### 3.3 🟠 태양광 인허가 절차·법령의 실무 확정

시드 데이터를 만들려면 **실무 판단**이 필요합니다. 제가 조문을 찾아 초안을 만들 수는 있지만, 확정은 담당자 몫입니다.

확인이 필요한 지점:
- 발전사업허가 소관 분기 — 3MW 이하 시·도지사 / 초과 산업통상자원부 (풍력과 경계가 다름)
- 개발행위허가의 지자체별 운영 편차
- 농지전용 vs 타용도 일시사용(염해농지) 중 사내 표준 경로
- 소규모환경영향평가 대상 규모 — 시행령 별표4의 태양광 항목

### 3.4 🟡 추가 API 키 발급 (기획서 §7.2 W1 항목)

이미 연동된 것 외에 태양광 특화 항목을 넣으려면 필요합니다. **1차 구현 범위에는 포함되지 않았습니다** — 넣기로 하면 알려 주십시오.

| 데이터 | 기관 | 용도 | 현재 상태 |
|---|---|---|---|
| 농업진흥지역·영농여건불리농지 | 농림축산식품부 / V-World | 태양광 부지의 상당수가 농지 | 미연동 |
| 일사량 자원지도 | 한국에너지공단 / KIER | 풍황을 대체하는 자원 평가 축 | 미연동 |
| DEM(수치표고) | 국토지리정보원 | 산지 평균경사도·향(남향) 분석 | 미연동 |
| 도로명주소 도로 레이어 | 행정안전부 | 도로 이격 버퍼 (태양광 조례 대부분이 도로 기준) | 부분(OSM) |

### 3.5 🟡 파일럿 부지 지정 (기획서 §8.1)

"실제 후보지 2곳(풍력 1·태양광 1)을 시스템과 수작업으로 이중 검토"가 검증 계획입니다. **태양광 파일럿 부지 1곳**을 지정해 주시면 판정 대조표를 만들겠습니다.

## 5. 지금 바로 확인하는 방법

1. 브라우저에서 http://localhost:5173 접속 후 로그인
2. 왼쪽 메뉴에 **`태양광 입지검토`**가 보입니다 (풍력 아래, 태양 아이콘)

**현재 조례 항목은 `확인 필요`로 나옵니다** — §3.1의 IP 등록 전까지는 조례를 물어볼 수 없기 때문이며, "규정이 없다"가 아니라 "물어보지 못했다"로 정확히 표시됩니다. 나머지 규제 62개 항목·면적 분포·제약도는 지금도 정상 동작합니다.
