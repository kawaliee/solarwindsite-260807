# 전기위원회 자료 — 발전사업허가 사례 대조

발전사업허가 **사례 대조**의 원본이다. 사용자가 검토 중인 사업지와 **실제로
심의를 거친 사업**을 견주어, 규제 판정에 "이 지역에서 이 정도 사업이 실제로
되고 있다"는 사실을 더한다.

⚠️ **점수·판정에 반영하지 않는다.** 사례는 참고 사실이지 허가 가능성의
근거가 아니다. 이유는 아래 「왜 확률로 만들지 않는가」를 보라.

```bash
docker compose exec backend python manage.py sync_korec
```

## 무엇을 모으는가

| | 건수 | 무엇이 들었나 |
|---|---|---|
| **3MW 초과 발전사업 허가대장** | **3,230행** (2001~) | 사업자·위치·원동력·용량·허가일·준비기간·변경사항 |
| **위원회 개최결과** | **141회차 · 2,880안건** | 회차별 의결 — **부결·보류와 그 사유까지** |
| **위원회 회의록** | **165회차** | 안건별 사업주체·최대주주·지번·설비용량·총사업비·위원 발언요지 |
| **허가취소 공고** | **23건 · 138사업** | 취소 처분 91 · 청문 예고 47 — **허가받고도 좌초한 사업** |

결과는 두 갈래로 나온다.

    전기위원회_사례.xlsx    사람이 보는 것 — 6시트
    cases.json             보고서가 읽는 것 — 판정에 쓰는 열만 간추림

원본 PDF·HWP는 `pdf/`에 그대로 남겨 둔다 — **판독이 의심스러울 때 사람이
직접 열어 볼 수 있어야 하기 때문**이다.

## 왜 이 자료인가 — 표준데이터를 버린 이유

앞서 검토한 「전국태양광발전소 전기사업허가정보 표준데이터」(공공데이터포털
15107742)는 **당사 사업 규모에 맞지 않았다.** 실측 결과다.

```
전국 125,229건 중
   3MW 이상        28건       ← 당사 최소 규모
 100MW 이상         3건       ← 당사 주력 규모

홍성군 963건 · 최대 1MW    ← 3MW 이상 0건
장흥군 847건 · 최대 1MW    ← 3MW 이상 0건 · 좌표 보유 1건뿐
```

소규모 태양광 등록부라 대형 사업 선례가 없다. 데이터 오염도 있다
(441m² 부지에 설비용량 3,630,562,275kW = 3.6TW로 기재된 건 등).

**전기위원회는 3MW 초과만 심의**한다. 당사 사업 구간(3~100MW)과 정확히
겹치고, 같은 지역을 여기서 세면 홍성 4건·장흥 1건(99MW)이 나온다.
무엇보다 **부결·보류 사례가 함께 실려** 생존 편향이 덜하다.

```
개최결과 2,880안건   가결 1,845 · 조건부 244 · 보류 680 · 부결 91
그중 태양광 491건    가결  223 · 조건부  86 · 보류 152 · 부결  30
```

## 판독에서 걸린 것들

### ⚠️ 서버가 프로그램 요청을 가려낸다

첨부는 `/commonfile/fileDownLoad.do`에 POST해서 받는데, 평범한 요청에는
**파일 대신 사이트 배너 JSON**이 온다(200 OK, `application/json`, 11,912B).
브라우저에서는 정상적으로 받아진다.

차이는 헤더였다. 실제 내려받기는 폼 전송(`target=_blank`)이라 **내비게이션
요청**인데 프로그램 요청에는 `Sec-Fetch-Mode: navigate`가 없다. 그 헤더를
붙이자 곧바로 `application/pdf`가 왔다. `korec.NAV_HEADERS`를 지우지 말 것.

### 첨부 형식이 섞여 있다

개최결과 141건 중 **HWP 118 · PDF 23**이다. 게시판은 어느 쪽이든 같은 이름
으로 올려 두므로 **파일 첫 바이트로 갈라야** 한다(`korec.read_document`).

### 편집 얼개가 열 해 사이에 세 번 바뀌었다

```
제159~215차   <원안의결> <보류>          건수 없음 · 항목이 '- '
제216~304차   허가기준 충족(14건)        항목이 'N.' · 사업자명이 붙는다
제305차~      허가 (23건)                항목이 'N.' · 지역명이 앞에 붙는다
그 밖에       서면심의·의결서 서식, 서면심사 한 줄 결과, 한전 약관만 다룬 회차
```

가운데 얼개가 가장 알차다. `궁항해상풍력발전(주)의 해남 궁항해상풍력
발전사업 허가(안)`처럼 사업자·지역·사업명이 한 줄에 들어 있다.

**136/141회차**가 판독된다. 남은 5회차(197·213·214·232·240)는 한전
기본공급약관이나 전력시장 운영규칙만 다뤄 **발전사업 안건이 없다** — 판독
실패가 아니다. 명령이 이 둘을 구별해 적어 준다.

### 회의록도 형식이 갈린다 — 그리고 PDF 쪽은 본문이 이미지다

회의록 165건 중 **HWP 142(제152~302차) · PDF 23(제303~326차)**이다. HWP는
글자가 그대로 들어 있어 바로 읽힌다. **PDF만** 세 겹으로 막혀 있다.

1. **2-up 편집** — 842pt 가로는 A4 두 쪽을 한 장에 앉힌 것이다. 가운데를
   기준으로 갈라야 한다. 안 그러면 좌우 단 문장이 한 줄씩 번갈아 나온다.
2. **글자 순서가 뒤엉킴** — HWP에서 뽑은 PDF는 그려진 순서가 읽는 순서와
   다르다(`승인 건 - : 6`). 낱말 좌표로 줄을 다시 세워야 한다.
3. **본문이 이미지** — 제326차 실측: 14쪽 중 4~14쪽의 한글 텍스트가 0~40자,
   쪽당 이미지 30~50개. 눈에는 보이지만 텍스트 층에 없다. **OCR 말고는 길이
   없다**(tesseract `kor+eng`, 반쪽당 약 1.1초 · 회차당 30초).

⚠️ HWP를 PDF로 열려 하면 `unknown image file format`으로 **조용히 빈 쪽**이
되어 그 회차가 통째로 사라진다. 첫 바이트로 갈라야 한다.

그 대가로 얻는 것이 크다. 회의록에는 개최결과에 없는 것이 있다.

```
ㅇ 사업주체     : ㈜고흥그린태양광        ㅇ 설비용량 : 40.32MW
ㅇ 최대주주     : ㈜제이투솔라            ㅇ 총사업비 : 483.84억원
ㅇ 발전소 위치  : 전남 고흥군 풍양면 안동리 767-2 등 59필지
ㅇ 공사계획인가기간 : ~2033년 4월   ㅇ 사업준비기간 : ~2034년 4월
위원 발언요지   : 계통 보강 이후 연계가능하다는 한전·전력거래소의 의견을
                  반영하여, 이에 대한 사업자의 동의 여부 확인 후 조건부 허가
```

**지번 단위 위치와 조건부 사유**가 여기 있다. 개최결과만으로는 "조건부 허가"
넉 자로 끝난다.

### 회차 매칭은 이름이 아니라 번호로 한다

회의록도 개최결과와 **같은 구획 얼개**(의결 유형 → 연번)를 쓰므로
`회차+의결유형+연번`으로 잇는다. 이름으로 잇지 않는 까닭은 회의록이 OCR을
거쳐 글자가 조금씩 틀어지기 때문이다(`LTE`→`11`, `㈜`→`수`/`때`).

그래도 번호만 믿지는 않는다. 이름의 두 글자 조각이 절반도 겹치지 않으면
**잇지 않고 비워 둔다**. 틀리게 잇느니 비는 편이 낫다 — 사례 대조는 사람이
읽고 판단하는 자료다. (실측 제326차 매칭률 88%)

같은 안건이 회의록에 **두 번** 나온다. 앞머리 'Ⅱ 상정 안건' 목록에는
**사유**가, 뒤쪽 'Ⅳ 심의안건' 본문에는 **사업주체·지번·용량·발언요지**가
실린다. 어느 한쪽만 쓰면 나머지를 잃으므로 둘을 이어 붙인다.

## 엑셀 시트

| 시트 | 무엇 |
|---|---|
| **허가대장(3MW초과)** | 3,230행. 사업 수를 셀 때는 `구분=최초허가`만 센다 |
| **회차별 안건** | 2,880행. 의결군·사업자·사유·**회의록 심의내용**이 한 줄에 |
| **회차 요약** | 회차별 안건 수, 태양광·풍력 건수, 가결/조건부/보류/부결, 회의록 유무 |
| **회의록 발췌** | 안건별 심의 내용 전문 |
| **허가취소** | 138건. 취소 처분과 청문 예고를 **구분해** 싣는다 |
| **지역별 집계** | 시·군·구 × 에너지원 — 검토 지역에 선례가 있는지 바로 보기 위한 것 |

### 허가취소 — 처분과 청문은 다르다

    취소 처분   이미 취소됐다(확정)
    청문 예고   취소하겠다고 알리는 단계. 소명하면 살아남기도 한다

섞으면 취소 건수가 부풀려진다. 판독기가 둘을 갈라 준다.

공고 서식이 해마다 달라 **23건 중 7건은 아직 못 읽는다**(2019·2023년 옛
단일 공고와 청문 공고 일부). 명령이 그 파일 이름을 찍어 주므로 직접 열어
확인하면 된다 — 조용히 빠지면 "취소된 사업이 없다"로 읽힌다.

### 허가대장은 한 사업이 여러 행일 수 있다

대장은 **허가와 그 뒤의 변경을 모두** 싣는다(3,230행 중 최초허가 581,
변경 2,649). `기타(변경사항)`가 비면 최초 허가, 내용이 있으면 그 뒤의
변경이다. 사업 수를 셀 때는 최초 허가만 세야 한다.

### 시·도 이름은 한 꼴로 모은다

2023년 개편으로 같은 삼척시가 `강원도`와 `강원특별자치도`로 갈려 나온다.
그대로 두면 한 지역이 두 줄로 세어져 **"선례가 적다"는 잘못된 그림**이 된다.
공백 없이 붙여 쓴 주소(`경북영덕군영덕읍매정리`)도 섞여 있어 첫 낱말만
떼어서는 안 된다.

## 왜 확률로 만들지 않는가

사례를 세어 "허가 확률 72%"를 내고 싶어지지만, 그 숫자는 근거가 없다.

1. **생존 편향** — 공시 자료에는 신청된 것만 있다. 조례 이격에 걸려 애초에
   접은 사업이 가장 많은데 그 모집단이 통째로 빠져 있다. (개최결과가 부결·
   보류를 담아 이를 **덜어 줄 뿐**, 없애지는 못한다)
2. **가른 변수가 자료에 없다** — 주민 수용성, 지자체장 의지, 지주 확보,
   계통 여유가 실제로 사업을 가르는데 공시 자료에 없다. 관측 가능한 것
   (용도지역·이격·경사도)만으로 만든 유사도는 허가 확률이 아니다.
3. **표본 부족** — 조례는 지자체마다 다른데 지자체당 사례는 몇 건이다.
   홍성군 태양광은 4건, 장흥군은 1건이다.
4. **자기실현적 왜곡** — "확률 30%"를 보고 접으면 그 사업은 신청되지 않아
   다음 통계에서도 빠진다. 시스템이 스스로 데이터를 편향시킨다.

그래서 **확률 대신 사실을 보여준다.**

```
같은 시·군 허가 사례   4건 (2025) · 최대 53.24MW
최근 사례             홍성빛나래솔라 53.24MW · 2025-08-26 허가
부결·보류 사례        인근 시·군 2건 — 계통 보강 대기 / 부지확보 미비
```

"옆 사업이 작년에 53MW로 허가받았다"가 "확률 72%"보다 쓸모 있다.
확률은 근거를 감추지만 사례는 확인할 수 있다.

## 보고서에 어떻게 실리는가

`PrecedentProvider`(`providers/precedent.py`)가 검토 지역·에너지원으로
`cases.json`을 조회해 판정 항목 하나를 만든다. 분류는 **사업성**,
상태는 **POSSIBLE 고정**이다.

점수 산식(`engine.py`)은 `CONDITIONAL`과 `UNKNOWN`만 센다. `POSSIBLE`은
`worst`·`spread`·`gap` 어느 항에도 들어가지 않으므로 **점수가 한 점도 움직이지
않는다.** 출력제어·소음민원 항목과 같은 얼개다.

보고서에는 종합평가 표의 한 줄과 별도로 **「인허가 사례 대조」 절**이 붙는다.
표 한 칸에는 사업명·용량·일자·사유가 건마다 다른 목록이 들어가지 않기 때문이다.

    허가 사례              허가일 · 설비용량 · 사업자 · 위치 · 사업준비기간
    보류·부결·조건부 사례    회차 · 의결 · 안건 · 사유
    허가를 받고도 좌초한 사업  구분 · 처분일 · 사업명 · 사업자 · 용량 · 사유

⚠️ 절 첫머리의 "판정·점수에 반영하지 않습니다" 안내를 지우지 말 것. 표만
남으면 다음 사람이 "선례가 많으니 되겠다"로 읽는다.

## 아직 안 쓰는 것

공지사항에는 **허가취소 처분 공고 23건**도 있다(HWPX). `봉화풍력 발전사업 등
7개 발전사업 허가취소`처럼 **허가를 받고도 좌초한 사업**이 실려 있어 사례
대조에 값어치가 있으나, 아직 수집 대상에 넣지 않았다.
